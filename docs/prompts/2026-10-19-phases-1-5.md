1.2 Customer-first rule (founder's words: nothing that negatively affects our customers)
Applies to sellers and their buyers. Never ship:

* Dark patterns. No fake scarcity ("only 2 left" unless stock really is 2), no fake countdowns, no fake "X people viewing", no fake reviews, testimonials or ratings, no pre-ticked upsells, no hidden fees.
* A badge or trust mark that isn't backed by data. A "Verified" badge shows only for stores that are actually verified. "COD available" shows only if the store has COD on.
* Demo or sample content that a buyer can buy. Sample products in theme previews are preview-only. They never become purchasable products, and never appear on a live store unless the seller explicitly converts them into their own product.
* Silent data loss. Changing theme, restoring a version or migrating settings must never delete the seller's products, images, text, menus or domains.
* A change that alters a live store without the seller pressing Publish (see §4.4).
* Anything that makes a store slower than the budgets in §4.8.

4.9 Security for themes and D-Studio (attackers will try this; the founder's friends will)
Settings JSON:

* validated server-side against a strict schema on every save and publish (unknown keys rejected)
* size cap (e.g. 512 KB)
* section types are an allow-list per tier
* free-form HTML is never stored

Text and links:

* rich text is a limited, sanitized subset (bold, italic, link, list, heading)
* links must be `https:`, `mailto:`, `tel:`, a WhatsApp URL or relative; `javascript:`, `data:` and `vbscript:` are rejected
* `rel="noopener noreferrer"` on external links

Custom CSS (RISE):

* parsed and sanitized server-side
* scoped to the store root
* no `@import`, no `url()` except the store's own media host, no `expression`/`behavior`/`-moz-binding`, no `position:fixed` overlays over checkout
* size cap
* checkout and order-status pages never load custom CSS (an anti-phishing and anti-overlay rule)

No custom JavaScript anywhere. The storefront CSP stays strict.
Media uploads:

* signed upload
* MIME sniffed from bytes, not the extension
* allow-list jpg/png/webp/avif/gif/mp4
* SVG either rejected or sanitized and served as an image only
* images re-encoded, EXIF/GPS stripped, max dimensions and size enforced
* per-tier storage quota
* served from the media origin with `Content-Type` fixed and `X-Content-Type-Options: nosniff`

No server-side fetch of seller-supplied URLs (SSRF). If image-by-URL import exists, it goes through an allow-listed, private-IP-blocking fetcher, or is removed.
Access control:

* IDOR tests: seller A cannot read, save, publish, restore or preview seller B's draft, versions, media or preview link
* staff permission checks on publish
* preview links are signed, expiring and draft-scoped

Rate limits: autosave, publish, upload, Report-this-store.
XSS test suite: the standard payload list goes into every text field, alt text, menu label, blog post, product title and CSS, and is asserted to render inert on storefront, preview, email and admin.
